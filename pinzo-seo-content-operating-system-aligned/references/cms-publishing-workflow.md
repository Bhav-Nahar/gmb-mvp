# Pinzo CMS Publishing Workflow

Use this when preparing content to go live.

## Pre-writing

1. Confirm mapped URL.
2. Confirm page type.
3. Confirm parent/child relationship.
4. Pull internal links.
5. Select lead magnet.
6. Confirm feature status.
7. Confirm schema type.

## Writing

1. Create answer block.
2. Build H2/H3 outline.
3. Add examples and checklists.
4. Add Pinzo-specific workflow.
5. Add CTA blocks.
6. Add FAQs.
7. Add source notes for Google process pages.

## CMS packaging

Include:

- slug
- title tag
- meta description
- canonical URL
- H1
- excerpt
- body markdown or HTML
- schema suggestion
- FAQ
- internal links
- CTA blocks
- lead magnet
- image brief
- alt text
- tracking events
- QA checklist

## Technical QA

- URL is lowercase and hyphenated.
- Page is indexable.
- Page has self-canonical unless there is a pSEO duplication reason.
- Primary content is server-rendered or pre-rendered.
- Images are compressed and named descriptively.
- Schema is validated before live.
- Sitemap updates happen after publish.
- GSC segment is tracked by folder.

## Post-publish

1. Submit sitemap or request indexing for P1 pages.
2. Track GSC impressions weekly.
3. Track CTA clicks and lead quality.
4. Add internal links from old pages.
5. Refresh GBP process pages every 60-90 days.
